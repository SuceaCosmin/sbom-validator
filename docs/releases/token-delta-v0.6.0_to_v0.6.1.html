Adopted Improvements and Regressions

Adopted

  • Measured telemetry replaces estimated session totals (resolves the long-standing "record dispatch tokens" recommendation).
  • Architect consolidated to a single dispatch (v0.6.0 used 3).
  • Single session; no context-reload penalty.
  • Zero CI lint/format cycles for the sixth consecutive release; no reactive doc fix dispatch.

Regressions / New Friction

  • G8 NO-GO on a pre-existing spec defect, followed by a six-dispatch rework chain; measured rework ratio is above v0.6.0's estimate.
  • Two cold-started re-reviews of the 5.S1 diff, then a separate minors fix round and a second G8/G6, all repeating the same verification.
  • Planner and docs-writer cost is disproportionate for a patch (planner is the largest subagent dispatch).
  • Orchestrator main thread is 38.6% of spend, with output dominated by long tracker evidence.

Efficiency Verdict and Forecast

Verdict: Flat (scope-normalised). Absolute spend fell sharply and there was no session boundary penalty, but the scope was a patch, so that drop is expected. On indicators that do not depend on scope the picture is mixed: rework ratio regressed (17.0% measured vs ~10 to 15% estimated), the release gate cost a NO-GO cycle, and the orchestrator and planner are heavy for the work. Confidence: Low to Medium (basis mismatch).

Projected next-release token range EST: a similar patch with the PR-time binary smoke in place and minors batched: ~2.6M to 3.6M input-eq (~80k to 110k fresh in+out). A v0.6.0-scale feature release on the measured basis: ~8M to 14M input-eq (extrapolated; there is no prior measured feature release, so low confidence).

Methodology and Confidence

v0.6.1 values: MEASURED from telemetry-v0.6.1.json (session 17e6ceae, cutoff 2026-10-07T20:54:39Z; G9 itself, G10 and closeout excluded). v0.6.0 values: EST as published in token-report-v0.6.0.html (orchestrator summaries apportioned; +/-15 to 25% per agent). Assumptions: (a) main-thread session totals and subagent totals are disjoint (inferred from cache_creation magnitudes); (b) input-equivalent = input + 0.10 cache_read + 1.25 cache_creation; (c) rework classification (5.S1, 2 x 5.S2, fix round, G8 attempt 2, G6 re-run) is analyst judgment. The percent change in the topline row compares different bases and is directional only. Forecast ranges are estimates.
