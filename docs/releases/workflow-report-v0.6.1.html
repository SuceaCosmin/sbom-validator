4. Top Workflow Wins

  1. G8 did its job. The release-manager built and ran the real binary and found 9 failing smoke checks (FileNotFoundError _MEI*/schemas/spdx.schema.json), a defect that would have failed release.yml at tag time or shipped broken binaries. The orchestrator verified it independently (4 of 13 schema files bundled) and routed the scope change to the human, decision recorded.
  2. Independence preserved under pressure. After the scope change G4 and G5 were re-run as two new parallel cold agents rather than self-reviewed; security showed the pre-fix state was fail-closed, which fixed the CHANGELOG wording about v0.6.0 binaries.
  3. No ADR deviation, no MAJOR findings. v0.6.0's top gap (ADR-010 deviation, 2 MAJOR) did not recur; the architect verified against locked click 8.3.2 and the code matched the amendment.
  4. Strong TDD evidence. 6 tests failed for the right reason first, 15 regression guards locked behaviour, cli.py coverage 99%, Compatibility Contract untouched.
  5. Minors batched into one fix round (glob filter, python fallback, CHANGELOG note, weak assertion, gotchas wording) with the KB write-back on the same branch.
  6. Single session (v0.6.0 needed two), and the orchestrator's stash-baseline check proved the 3 local mypy yaml errors pre-existing before CI confirmed mypy clean.

5. Top Workflow Gaps (with root cause)

  1. PyInstaller spec defect found only at G8. Root cause: ci.yml never builds the binary; scripts/smoke-test-binary.sh runs only in release.yml on tag push. The spec bundled 4 of 13 schemas already in v0.6.0 (tracker: verified with git show v0.6.0:sbom_validator.spec); the old 14-check smoke only exercised formats whose schemas were bundled, so it could not fail (inferred). The v0.6.0 G8 report recorded "PyInstaller spec verified", a false assurance. Cost: NO-GO chain, 5.S1, two re-reviews, fix round, G6 and G8 re-runs, 17.0% rework.
  2. Test 5b written but wired to nothing. The tester put it in tests/smoke/test_binary_smoke.sh, which no workflow calls, and recorded "deferred to CI". No agent definition asks "which check runs this?".
  3. Draft PR before closeout. Root cause: planning assumed PR-after-closeout without checking that ci.yml is PR-triggered. The deviation was sound, human-approved and recorded under G6, but task 5.H2 still shows pending and depends on 6.J1, so the tracker contradicts reality.
  4. Branch mixes migration with release content. The human chose to branch from 6d72d63 because the hil-team contract was not on develop. Trade-off: no separate onboarding PR needed, but the H2 reviewer sees migration plus R-12 in one diff and cannot revert them independently. Mitigated by the migration being its own commit (though it also contains the release tracker).
  5. Unreviewed fix commit. 7f4ca5b changed sbom_validator.spec (glob filter), the smoke script and tests after the 5.S2 verdicts on 36c112d. G6 re-run and G8 attempt 2 (smoke 24/0, 732 passed) verified it, but no G4/G5 delta pass or waiver is recorded. Low risk, rule gap (inferred: verdicts scoped to 36c112d).
  6. Disproportionate patch overhead. Planner 509k input-eq (12.1%) for one parameter; 17 dispatches; six cold-start rework dispatches. No patch profile exists in the planner or gate model.
  7. Telemetry collector fallback. usage.db lacked this session, so telemetry was rebuilt from Claude Code transcripts through a scratchpad wrapper (session_source: transcripts). The result is MEASURED and valid, but the workaround is manual and unrepeatable, the cutoff (20:54:39Z) predates G9/G10/closeout (the token analyst estimates a ~0.4-0.9M tail, EST), and there are no per-dispatch timestamps.
  8. Release-manager attempt-1 factual error (diff touching schema_validator.py and test_schema_bundle.py); caught by the orchestrator, but an unverified claim in a GO/NO-GO brief is a trust risk.
  9. Local environment drift. mypy showed 3 yaml import-untyped errors locally because types-pyyaml was not installed; this cost an orchestrator baseline investigation. CI was clean.
