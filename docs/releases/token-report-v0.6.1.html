    Largest single subagent dispatch for a one-parameter change. Cache creation of 379,737 tokens (cost-weighted 474,671) shows a large first-load of KB/ADR/source context; 14 turns produced only 1,214 output tokens.
  4. Subagent cold-start context (cache creation): 1,809,648 (42.9%)
    Every dispatch writes 22k to 380k tokens of cache before working. Six of the 17 dispatches are rework re-dispatches that paid this again.
  5. Docs sync: 242,270 (5.7%) and architecture: 227,472 (5.4%)
    Each took 20 turns for a patch-size change (one ADR amendment; four small doc edits). Reasonable but at the upper end for the scope.

Methodology and Confidence

Measured: every token count in the summary, per-agent, per-dispatch and per-gate tables comes from telemetry-v0.6.1.json (transcript-derived; session 17e6ceae, generated 2026-10-07T20:54:39Z, last turn 20:54:37Z). Per-gate and per-family figures are sums of measured dispatches mapped by dispatch description to tracker task IDs. Derived (not estimated): input-equivalent uses the fixed weights cache_read 0.10 and cache_creation 1.25; output is excluded from it.

Estimated EST: the G9/G10/closeout tail, orchestrator steering cost inside the rework chain, and all savings figures. Savings are ranges anchored on the measured cost of the dispatches they would avoid.

Limits: (1) Disjoint main + subagent aggregation is inferred from the data, not documented by the collector; subagents are 61.4% of the total. (2) The orchestrator cannot be split per gate. (3) Rework classification is analyst judgment. (4) Command repetition (full-suite runs) comes from tracker evidence, not telemetry. (5) Session totals will grow after the cutoff.

Confidence: token counts High; aggregation assumption Medium; rework classification Medium; savings Low to Medium.
